# Documentation and contract review

Historical audit of the original design. The [active MVP decisions and dispositions](agentic-learning-platform/docs/ARCHITECTURE.md#review-disposition) describe the integrated specifications. The baseline source links below point to the reviewed commit.

Review of the project at commit `404d0d5`. The checkout had 66 tracked files. Twelve contained text and 54 were empty scaffold files. This review covers the root specs, the copies in the scaffold, both READMEs, the transcript, the existing review, and text configuration. It also checks the university and paper references used in the findings. The original files remain available as evidence.

## Main blockers

| Priority | Decision or contract | Why it blocks integration |
| --- | --- | --- |
| 1 | Define learning objectives and link them to courses, topics, outcomes, prerequisite edges, and assessment targets. | Every agent needs to agree on what the learner is studying, attempting, or demonstrating. |
| 2 | Confirm the MVP workflow at goal preview. | Assessment adds an optional pre-planning diagnostic that the current Planner and Orchestrator cannot start or consume. |
| 3 | Define assessment results and progression together. | A pass on a targeted check must have a different effect from completion of a course. Carry-forward, skips, and conflicting evidence still need decisions. |
| 4 | Define the private grading snapshot and objective evidence report. | The Assessment Engine needs enough frozen data to grade a retry. The Curator needs enough detail to apply that result to the right objective once. |
| 5 | Publish a single shared contract for each agent and define the Curator-owned learner record. | The existing specs differ on persistence and required fields. The scaffold has duplicate specs, broken pointers, and no functioning implementation. |

The walkthrough established **full curriculum first, then optional course-entry familiarity**, with the Curator supplying context to both agents and owning the main database writes. Assessment’s new pre-planning diagnostic is an additional feature proposal. The recommendations below preserve the agreed flow where possible and identify decisions that change it.

## 1. Planner and curriculum contract

1. **There is no producer for objective IDs.** Planner emits topic identifiers and course-level expected outcomes. The Tutor needs an objective ID to teach, Assessment needs it to grade, and the Curator needs it to store evidence. Define an observable objective record with an ID, course and topic links, priority, depth, outcome links, demonstration requirements, and sources. Make the Planner produce it and define the scope of its ID. This is the existing R-001 blocker. [Planner output](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_PLANNER.md#L55) · [Tutor input](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/TUTOR.md#L51) · [Assessment targets](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L65)

2. **Topics, objectives, outcomes, and depth are disconnected.** A topic can contain multiple independently assessable skills. A prose demonstration statement and undefined depth label give agents room to choose incompatible tasks. Define a small depth vocabulary and specify what evidence demonstrates each objective. Temporary topic targets can support a prototype, though a topic-level failure cannot reliably tell the Tutor which skill to remediate. R-013, R-014, R-036, R-037. [Planner syllabus](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_PLANNER.md#L57) · [Assessment target alignment](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L164)

3. **A DAG edge names a skill in prose but access control needs a reference.** The edge must identify the upstream objective and the downstream dependency. Decide whether a verified upstream skill clears its particular edge or whether the entire upstream course must pass. The Curator’s structural checks cover cycles, course references, and syllabus existence. The Planner also requires upstream skill coverage at the right depth. Define which checks the application can perform from identifiers and which require academic judgment. [Planner DAG and validation](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_PLANNER.md#L55) · [Planner prerequisite rule](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_PLANNER.md#L79) · [Curator publication checks](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_ORCHESTRATOR.md#L93)

4. **The route’s completion and branch semantics are undefined.** The Planner can propose multiple possible directions and shared foundations. The Curator checks “every required prerequisite branch,” but there is no representation for an elective branch, a choice between alternatives, or the completion condition for a milestone or goal. Decide how a learner selects a direction and how that selection changes required work. An illustrative route is enough for the demo if its required branches and finish condition are explicit. 5. **Assignments refer to topics, while the Curator and Tutor act on objectives.** A recommendation to skip a topic could cover several mandatory objectives. Define how topic-level study, review, or skip recommendations expand into objective assignments, and how the Curator selects the next objective. The Tutor’s responsibility table assigns study assignments to both the Planner and Curator. The Planner recommends and the Curator applies the assignment. 6. **A replan lacks a progress migration contract.** The Curator is told to check whether older results still apply, but the Planner publishes a complete replacement with no objective equivalence map or compatibility rules. ## 2. Diagnostic and familiarity workflow

7. **The optional pre-planning diagnostic is outside the current shared workflow.** Assessment places it between preview and curriculum generation. The Planner has no diagnostic summary input, and the Curator’s assessment action requires a course session that can only exist after the curriculum. The diagnostic acceptance tests already expect the route. Decide whether to defer it or add a goal-preview attempt route, explicit opt-in and stop behavior, and a Planner input before making those tests mandatory. R-002, R-003, R-034. [Assessment diagnostic action](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L46) · [Planner inputs](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_PLANNER.md#L40) · [Curator inputs](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_ORCHESTRATOR.md#L53)

8. **Grading purpose needs to travel with the result.** The Curator applies the progression policy after a generic graded report. A diagnostic can inform planning, a targeted check can guide assignments, a verification can cover a subset, and a course completion can clear a course. Each report and transition needs purpose, scope, and eligibility so a generic `passed` result cannot accidentally complete a course. R-004, R-053. [Curator grading report](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_ORCHESTRATOR.md#L87) · [Assessment purposes](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L48) · [Assessment outcome](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L118)

9. **Diagnostic areas have attempt-local IDs and no mapping to subsequent coursework.** Assessments distinguish direct diagnostic evidence from self-report, but the shared context has no contract for either the mapping or the allowed use. A later familiarity question can reuse relevant information if it is explicitly linked and advisory. Scope the diagnostic to its goal preview and define behavior when the goal changes, the learner stops, or grounding is unavailable. R-031, R-033, R-035, R-042. [Diagnostic targets](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L65) · [Diagnostic summary](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L135) · [Planner familiarity input](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_PLANNER.md#L41)

10. **The diagnostic budget and partial-submission protocol are proposals.** The ten-prompt cap is neither an approved count nor a time limit. The grading contract needs a way to distinguish a learner who declines, one who stops after answering some prompts, and one who loses the connection. Specify how self-report prompts, direct tasks, and unanswered items appear in the saved submission and in the learner summary. R-032, R-035. [Assessment submission input](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L63) · [Diagnostic rules](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L217) · [Partial diagnostic handling](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L258)

11. **The familiarity question can become repetitive or open-ended.** The Curator can send follow-up prompts, but the specs give no stop rule, decline behavior after a follow-up, or reuse rule when the learner reopens a course. The current goal-preview inputs name interests and intended direction, so repeated background questioning is a risk rather than a behavior already specified there. Reuse relevant answers and ask again only when a specific unresolved objective can change the assignment. R-055. 12. **The threshold for a self-reported skip is intentionally open.** Define the difference between skipping instruction and clearing a prerequisite. A learner may skip familiar material, complete the remaining work, or enter a clearance assessment directly. ## 3. Assessment correctness and progression

13. **Pass criteria, policy ownership, and grade display require one decision.** Assessment proposes a versioned policy supplied by the Curator, assigns policy decisions to the project owner, and later says ownership is open. Specify who approves and maintains the policy, who supplies its version, and who applies it. Assessment decides the attempt outcome under that policy. The Curator applies course progression. Decide the displayed categorical result and whether a numeric grade is a feature. Tie mandatory acceptance tests to the adopted policy. The current list already requires some provisional behavior, including the skip path and diagnostic. R-010, R-011, R-030. [Policy responsibility](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L35) · [Proposed pass rule](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L203) · [Policy dependency](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L239) · [Acceptance criteria](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L271)

14. **The review and Assessment spec disagree on mixed results.** The Assessment rules check failed or partial mandatory targets first. One definite failure plus one inconclusive target therefore yields `not_passed`. Review’s MD-01 says any unclear target makes the outcome inconclusive. Specify the precedence and add a mixed-result fixture. Also distinguish an operationally pending attempt from a completed but inconclusive result. [Explicit Assessment rule](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L203) · [MD-01](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/review.txt#L684) · [Curator inconclusive handling](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/LEARNING_ORCHESTRATOR.md#L126)

15. **The aggregation rules leave empty cases that can accidentally pass.** “All required criteria met” is true for an empty required-criteria set in a typical implementation. A course completion with no in-scope mandatory targets can similarly reach the “otherwise passed” rule. Validate nonempty required criterion coverage for every mandatory target, require the published mandatory target set for completion, and explicitly handle unassessed targets before aggregation. [Criterion contract](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L109) · [Status and pass rules](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L194) · [Coverage acceptance](https://github.com/IbrahimMI124/Multi-Agent-Adaptive-Tutoring-System/blob/404d0d50c1adfd9f16b5aa8ded6178f7e1db6cd0/ASSESSMENT.md#L263)

16. **Carry-forward and verification can yield two different kinds of success.** Verification deliberately checks only missed targets. Its pass must be interpreted alongside eligible prior evidence for every mandatory course objective. Define whether a targeted check can count toward completion, whether the evidence must come from the same version and policy, how conflicting or expired evidence is handled, and what the learner sees when only a subset passes. 18. **Per-target evidence and criterion judgments lack join keys.** The evidence and judgment field lists do not explicitly require the target ID, item ID, criterion ID, or references from evidence to the judgments that produced it. 19. **Stateless replay is possible, but identical rubric grades are not guaranteed by the spec.** The retry rule allows open-answer rubric judgments to vary. ## 7. Order of work and integration checks

1. **Freeze the cross-agent language.** Define objectives and version-scoped IDs, curriculum edge semantics, learner evidence kinds and allowable uses, and the per-purpose assessment input and output. Put the shared contract in one tracked place. Update the active agent specs against it.
2. **Choose the shortest defensible MVP flow.** Keep the agreed preview, full curriculum, and optional familiarity path for the first integration. Treat the pre-planning diagnostic as a feature decision with a defined route if accepted. Agree on pass precedence, skip clearance, targeted checks, partial verification, and what counts toward course completion.
3. **Make the Curator’s state transitions executable with stubs.** Pin down attempt allocation, snapshot contents, authorized state changes, retry behavior, and outcome applicability across curriculum versions. Use a small approved library and one complete course plus a successor once the shared contracts are ready.
4. **Verify the difficult paths together.** Run these as cross-component acceptance scenarios with a stub or seeded course before relying on generated content.

| Scenario | Expected behavior to specify and test |
| --- | --- |
| Learner knows most of a course | An objective-level assignment avoids redundant instruction. An agreed clearance policy governs access to the successor. |
| Tutor observes a correct answer after a hint | The result can inform readiness or teaching strategy. Demonstrated knowledge is recorded through the approved evidence path. |
| Assessment definitively fails one target and cannot score another | The outcome follows the approved precedence, and both pieces of feedback remain visible. |
| Learner passes a targeted check or a subset verification | The Curator applies evidence only to its scope and completes the course only when the full approved rule is met. |
| Mandatory target has no valid criteria, key, or permitted source material | The preparation or validation path reports an actionable issue and the course remains recoverable. |
| Preparation or submission is retried and responses arrive out of order | The saved attempt stays consistent. One accepted outcome causes one set of progress effects. |
| Learner resumes an open assessment or replaces the plan while grading is in flight | The attempt retains its exact or immutable inputs, and the result is applied only to an eligible version and objective. |
| A conversation summary finishes after assessment evidence is saved | The summary updates its own transcript range. The new evidence is available in the next relevant worker call. |
| Two learners request the same course or resource | Shared educational provenance can be reused. Session, evidence, and attempt data stay scoped to the authenticated learner. |

The course project can demonstrate these behaviors with a small set of fixtures. Question-bank scale, adaptive testing, certification, and a broader evaluation of educational effectiveness are separate scope decisions.
